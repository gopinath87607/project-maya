Nested prefill chunks

A prefill chunk is one token range that every GPU walks in order (layers 0-11 → 12-22 → 23-34 → 35-44), so today all four run the same size — the smallest part's. Nesting gives each part its own number, as long as it is a whole multiple of the part feeding it.

What it buys

  • Uses memory that is already free on the two 3060s instead of hunting for 600 MB on the 5060s.
  • Expert staging is the biggest item on a chunk (55% of CUDA0's 5,483 ms) — paying it once per 16k/32k instead of once per 8k is a real per-token cut on three of the four parts.
  • Nothing in the model changes: positions, KV and checkpoint marks are absolute.

What it costs

  • A piece's wall is Σ(parts) + (chunks−1) × max(part) — longer stages make the fill of every piece longer.
  • CUDA0 stays the pacing stage: it is the one part nesting does not speed up.
  • The hand-off loop assumes one hop per chunk — that bookkeeping (events, prestage, next-chunk plan) is the risky part, so it needs its own A/B.
